## 编号规则

| 层级 | 名称 | 格式 | 含义 |
|---|---|---|---|
| 一级 | 功能模块 | `M0x` | 业务域边界 |
| 二级 | 功能 | `M0x.F0y` | 一个完整闭环能力 |
| 三级 | 功能子项 | `M0x.F0y.I0z` | 技术交付单元（一个接口 / 一个页面 / 一个引擎件） |

**硬规则**

1. 编号单调递增，永不复用。废弃改状态，不删行。
2. 子项编号必须以父级为前缀。
3. 拆不出子项的功能 → 它其实是子项，往上并。子项超 20 个 → 它其实是模块，往下拆。

**状态**：`规划` | `开发中` | `已上线` | `已废弃`
**子项类型**：`接口` | `页面` | `组件` | `引擎` | `服务层`

## 本仓定位

AI 面试官：**会追问、记得住**的 HR 面试模拟 Agent。求职者上传简历、录入目标岗位 JD，
面试官基于候选人画像与岗位差距定制出题，像真人一样追问（含糊要证据、亮点往下挖），
每轮回答按维度即时评价入档，面试结束出结构化总评报告。
突出点 = **M02+M03 评价闭环**——「追问」与「评价档案」一体：追问由上一轮评价驱动，报告由全程证据汇总。
书籍映射：《图解AI Agent》第 10 章实战范式（PDF 简历解析 + JD 自动化打分 + 多轮面试模拟）；
书中 CrewAI/LangGraph 双框架叙事，本仓按既定纪律改为**手写 tool-use 循环**实现同等能力。
架构：FastAPI + OpenAI 兼容直调（MiniMax-M3，可配 base_url）+ React 18 前端。
